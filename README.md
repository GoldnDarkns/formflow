# FormFlow: private scanned-form and ID digitiser

FormFlow is an installable web app (PWA) that turns scanned forms, passports, ID cards, visas and licences into structured key–value data. All of the computer vision runs **inside the browser**, so personal data never leaves the device. There's no server, no account and no paid API.

MAIB AI 221 Computer Vision with Applications, Final Project 9 (Public sector).

| | |
|---|---|
| **User** | A back-office clerk digitising application forms and identity documents |
| **Decision supported** | Which extracted values can go straight into the system, and which need a human check |
| **Cost of an error** | A wrong passport number or date of birth on a file means rework or a rejected application, so uncertain fields are always flagged instead of silently accepted |

## What it does

1. **Drop a mixed pile.** Upload or photograph any number of pages in any order (phone camera supported).
2. **Magic scan** (for photos): find the sheet of paper (threshold, flood fill from the border, largest region, corner extremes), warp it flat with a homography, and even out the lighting by dividing by the local paper brightness. An animation shows the cut-out. PDFs are split into pages with pdf.js.
2b. **Clean up each scan**: deskew (projection-profile search), binarise (Otsu for flat scans, Sauvola when lighting is uneven, chosen automatically), and remove ruled lines.
3. **Read the text** with one of two readers, switchable in the app: Tesseract 5 LSTM (tesseract.js, the classical baseline and the default because it is the faster one) or PP-OCRv5 mobile (a neural text detector and recogniser, 12 MB of ONNX, implemented in `src/core/ppocr.ts`).
4. **Recognise the document type**: passport, Emirates ID, ID card, driving licence, visa or permit, form, or other. The decision uses the machine-readable zone, tell-tale text (titles, number formats such as 784-YYYY-NNNNNNN-N) and page layout. A softmax over the evidence weights gives the confidence, and the evidence is shown to the clerk, who can overrule it. Pages land in a tray per type.
5. **Label and link**: two gradient-boosted tree classifiers trained on FUNSD label each text block (question, answer, header, other) and link questions to answers. Both run as ONNX in the browser. Identity documents add a layout prior (small label above a larger value).
6. **Verify what can be verified**: the machine-readable zone is read from several crops and the reading whose check digits agree best is kept (ICAO 9303 formats TD1, TD2, TD3, MRV-A, MRV-B). Likely OCR confusions are repaired only when the composite check digit confirms the repair. Emirates ID numbers are checked with their Luhn digit.
7. **Key facts and alerts**: name, document number, nationality, dates (normalised to ISO) per document, with warnings for expired documents and ones expiring within six months.
8. **Cross-document checks**: documents carrying the same name are grouped, and their date of birth, name spelling and passport number are compared.
8b. **The critic**: checks each sorting decision three ways: whether the page contains what the type should contain, what argues for the runner-up type, and what an independent vision model (MobileCLIP-S0 image encoder, 46 MB, with text embeddings precomputed by `scripts/critic-embed.ts`) thinks from the picture alone.
9. **Trust score**: one figure per document that blends field confidence, type confidence and checksum results. Fields a person confirms count as certain.
10. **Second reader (generative AI)**: Florence-2 reads the page again through Transformers.js (WebGPU or WASM). Agreement raises confidence; disagreement flags the field and offers Florence-2's version.
11. **Review and export**: boxes, links and a highlighter mark over the image, an editable field list with close-ups and the doubtful fields first, then JSON, CSV or a PDF report (jsPDF). A redaction mode blacks out identity numbers on a copy of the image. A corrected document can be exported as a **labelled example** (FUNSD format) for testing or training.

## Results (FUNSD test set, 50 forms not seen in training)

The full tables are on the app's **Model card** tab, generated by `npm run evaluate`.

- **Question → answer linking F1 = 91.2%** with ground-truth text blocks (gradient boosting). The rule baseline scores 70.4% and logistic regression 81.0%.
- **Second-reader experiment:** when Tesseract and Florence-2 (two tiles) agree, a Tesseract word is right **93.0%** of the time. When they disagree, it is right only **48.2%** of the time. That gap is why agreement is used as a confidence signal. Splitting the page into two tiles cut Florence-2's character error rate from 53.4% to 29.9%.
- **End to end** (image → exact key–value pairs, strict 80% match on both key and value): F1 27%. This is the weak spot, mostly caused by OCR errors on old 1990s faxes.
- **Readers compared:** PP-OCRv5 cuts the character error rate from 20.4% (Tesseract with clean-up) to 13.1%, raises word accuracy from 63.8% to 76.7%, and lifts end-to-end F1 from 28% to 41%. It is about 3 to 4 times slower in single-threaded WebAssembly, so check the time on your own device before making it the default.
- **Magic scan:** on 20 simulated desk photos (perspective, clutter, shadow) the page was found 20 times out of 20 with a mean corner error of 0.4% of the diagonal, and word recall rose from 56.5% to 69.7%.
- **Critic's vision model:** 43 of 50 forms and 5 of 7 sample scans right on its own, so it only raises doubts. Its 8-bit version failed completely, and Florence-2 captions were too generic to name a type.
- **Document type:** 47 of 50 FUNSD forms are sorted as forms (94%), and 7 of 7 sample scans are sorted correctly. The identity documents among those samples are synthetic specimens, so this still needs testing on real documents.
- **Confidence figure:** it ranks fields well (1% correct in the lowest band, 60% in the highest) but is too optimistic in absolute terms on old faxes. The Model card shows the full table.
- **Speed:** about 3–4 seconds per page in the browser for the main pipeline. Florence-2 takes a few seconds per page on WebGPU, or 20–60 s on CPU.

## Run locally

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # production build in dist/
npm run preview      # serve the build
```

## Deploy (free)

**GitHub Pages:** push to a public GitHub repository, then go to *Settings → Pages → Source: GitHub Actions*. The workflow in `.github/workflows/deploy.yml` builds the app and publishes it on every push to `main`. The app uses relative paths, so it works under `https://<user>.github.io/<repo>/`.

Cloudflare Pages isn't used because it limits single files to 25 MiB, and the ONNX Runtime WebAssembly file is about 27 MB.

## Reproduce training and evaluation

Download FUNSD (<https://guillaumejaume.github.io/FUNSD/>) and unzip it into `../data/funsd/` (next to this folder). Then run:

```bash
npm run ocr -- training full     # Tesseract + pre-processing on 149 training forms (cached)
npm run ocr -- testing full      # ... and on the 50 test forms (also: raw / upscale / deskew / nolines for the ablation)
npx tsx scripts/ocr-funsd-pp.ts training pp 1600 && npx tsx scripts/ocr-funsd-pp.ts testing pp 1600   # PP-OCRv5 reader (models in public/models/ppocr)
npm run features                 # features for both classifiers (ground-truth and OCR text blocks)
pip install scikit-learn skl2onnx onnxruntime onnx joblib
npm run train                    # trains, compiles the trees to plain ONNX ops, verifies against sklearn
npx tsx scripts/florence-funsd.ts 1x1   # Florence-2 second reader on the test set (optional, slow on CPU)
npm run evaluate                 # writes public/eval/results.json (shown on the Model card tab)
```

`scripts/tree2onnx.py` compiles the gradient-boosted trees into standard tensor operations (Gather, LessOrEqual, MatMul, Equal), the same approach Hummingbird uses. This is needed because ONNX Runtime Web doesn't include the `ai.onnx.ml` tree operators. The compiled model matches scikit-learn exactly (100% agreement on predicted labels, |Δp| < 1e-6).

### Your own test set (passports, visas, licences, forms)

1. Process each document in the app, correct the fields, and click **Labelled example**.
2. Put each image and its `.labels.json` into a folder per document type, for example `../data/own/passport/`, `../data/own/visa/`, `../data/own/licence/` and `../data/own/form/`.
3. Run `npx tsx scripts/eval-own.ts ../data/own` to get precision, recall and F1 for each document type.

Only use documents you have the right to use: your own, ones with written consent, or official specimen images. Don't commit them to the public repository (`data/` is already in `.gitignore`).

## Responsible AI

- **Privacy:** everything runs on the device. There are no uploads, analytics, cookies or accounts, and export only happens when the user asks for it.
- **Human in the loop:** low OCR confidence, uncertain links, reader disagreement and failed check digits all flag a field for review. Nothing is auto-approved on the clerk's behalf.
- **Bias and limits:** the system works best on Latin-script print. Handwriting, Arabic script, stamps and checkboxes are weaker and are expected to be flagged. It doesn't check whether a document is genuine.
- **Licences:** FUNSD is for non-commercial research and education only, so this app is non-commercial.

## Project structure

```
src/core/        pipeline code shared by the browser and the Node scripts
  preprocess.ts  deskew, Otsu/Sauvola binarisation, line removal, resize
  ocr.ts         Tesseract result parsing, CER, hallucination and omission scoring
  layout.ts      word grouping, features, candidate pairs, link decoding
  scan.ts        magic scan: page detection, perspective warp, lighting correction
  critic.ts      the critic's expectation checks and verdict
  critic-vision.ts  zero-shot vision opinion (MobileCLIP image encoder)
  ppocr.ts       PP-OCRv5 reader: detection post-processing, batched CTC recognition
  classify.ts    document-type recognition with evidence and confidence
  facts.ts       key facts per type, date parsing, Luhn check, expiry alerts
  pipeline.ts    labels → links → fields, confidence, reader agreement, ID layout prior
  mrz.ts         ICAO 9303 MRZ parser with check-digit repair
  florence.ts    Florence-2 OCR_WITH_REGION wrapper (tiling, de-duplication)
  classifier.ts  ONNX Runtime wrapper (web and node)
src/engine/      browser orchestration and Web Workers
src/ui/          React interface
scripts/         OCR caching, dataset building, training, evaluation, browser tests
public/models/   the two ONNX classifiers (1.9 MB)
```
